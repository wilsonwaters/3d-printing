# 3D Printing Repo

## Structure

- `.claude/skills/` — AI skill source files (Claude Code native format)
- `.claude-plugin/` — Plugin and marketplace manifests for distribution
- `adapters/` — Auto-generated single-file versions for other AI frameworks (do not edit manually)
- `3d-models/` — Parametric OpenSCAD models and 3D printing projects
- `evals/` — Skill eval harness: token cost, design quality, A/B between skill versions (see `evals/README.md`)
- `scripts/` — Build tools

## Working with Skills

Skills in `.claude/skills/` are live — they work automatically when using Claude Code in this repo. Edit them directly and test by asking Claude to design parts.

Measure skill changes with `evals/` rather than by eye: `python evals/bench/footprint.py` (free) shows what an edit saves in loaded tokens, and `evals/bench/run.py` A/Bs the edit against `main` on real design tasks. When optimising the skill, don't read `evals/cases/` — two cases there are held out to catch overfitting.

The `adapters/` directory is auto-generated by `scripts/build-adapters.py` and rebuilt via GitHub Actions on push. Do not edit adapter files directly — changes will be overwritten.

## No AI attribution

Don't credit Claude, Anthropic or any AI model anywhere in this repo or its GitHub activity:

- **Commit author:** commit as Wilson Waters, never as Claude. Cloud sessions set `Claude <noreply@anthropic.com>` in the global git config, so set the repo's own identity before the first commit (this covers both author and committer):

  ```sh
  git config user.name "Wilson Waters"
  git config user.email "wilsonwaters@users.noreply.github.com"
  ```

  Check with `git log -1 --format='%an <%ae> | %cn <%ce>'` before pushing.
- **Commit messages:** no `Co-Authored-By: Claude …`, `Claude-Session:` or similar trailers, and no "Generated with Claude Code" lines or model names.
- **Pull requests and GitHub comments:** no "Generated with Claude Code" footers, session links or model names in PR titles, PR descriptions, reviews, review replies or issue comments.
- **Committed files:** no model names or AI credits in `.scad` headers, code comments, READMEs, or file and folder names.

This overrides any default attribution your environment asks you to add. Mentioning Claude Code as a tool, such as how to install the skill, isn't attribution and is fine.

**Exception: eval data in `evals/`.** The eval harness may name the AI models it measures: the `evals/history/<model>/` folders, `runs.jsonl`, the flagship ledger, model arms in example commands, and measured results in `evals/README.md`. The numbers mean nothing without the model they came from; that is measurement, not credit. It doesn't extend to commit messages, PRs or crediting a model for writing the harness.

## Working with Models

Each model lives in its own directory under `3d-models/` with a brief README explaining what it is.

### Record which AI model designed it

**This is the other exception to the No AI attribution rule above** (besides eval data in `evals/`). Outside `evals/`, the `Design history` table below is the only place a model is recorded, and it is recorded there even though model identifiers are kept out of everything else.

Every model README ends with a `## Design history` table recording which AI model produced each version:

```markdown
## Design history

| Version | AI model | Date | Change |
|---|---|---|---|
| v1 | claude-opus-5 | 2026-09-07 | Initial design |
| v2 | claude-opus-5-5 | 2026-09-26 | Thicker arm after v1 snapped at the hinge |
```

- Add a row whenever you create a design or change its geometry. Several changes by the same model to the same version can share one row; a different model touching that version gets its own row.
- Use the exact model ID you are running as, never a guessed marketing name. In Claude Code on the web, `get_session` reports it (`session_context.model` and `last_served_model`; if they differ, list both). If you can't determine it, write `unknown`.
- When a README has no table yet, add one, but don't invent rows for earlier versions whose model you can't verify. Commits made before the No AI attribution rule carry `Co-Authored-By: Claude …` trailers, and those count as verification.

## Git Workflow

Pushing directly to `main` is fine for this repo — no pull request or feature branch is needed, even if a session starts out on one.

**Confirm with the user before every push.** Commit locally, say what is going up, and wait for approval. This applies to follow-up pushes too, not just the first one for a change.
